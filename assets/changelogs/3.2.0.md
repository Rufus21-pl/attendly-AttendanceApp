# Version 3.2.0 Update 💾


### 🆕 New Features
* **Automatic Backup:** The app now writes a backup copy of each database by itself: a few seconds after each change, when the app goes to the background and when a database is closed. Two copies are kept per database, so no cleanup is needed.

* **Backup in Settings:** *Settings → Data → Database backup* shows the time of the last backup. A tap writes a backup at once.

* **Restore Screen:** If a database is missing, empty or damaged when the app starts, a new screen lists the backups of that database. Select one and tap *Restore backup*. The replaced file is not deleted, it is kept in the backup folder.

* **Restore After a New Installation:** If the app finds backups but no database on the first start, the start screen has the button *Restore from backup*.

* **Several "Open" Entries:** The *Number of Entries* field is now available for the Open category too. One person can get several Open entries on the same day, for example an anonymous person that stands for several visitors.

* **About Attendly:** The Settings show the author, the licence, the open-source licences and a contact link.


### 🔧 Improvements
* **Safer Data:** The database itself now refuses a daily entry for a person that does not exist, and refuses to delete a person that still has entries.

* **Up to Date:** The packages that Attendly is built on are updated to their newest versions.


### 💡 Good to Know
* The backup copies are stored on the same device, in `Documents/AttendlyDb/backup/`. They protect against a damaged or deleted database, not against a lost or broken device. Copy the `AttendlyDb` folder to another device from time to time.

* The app no longer stops a second Open entry for the same person on the same day. Check the daily log if you are not sure whether a person is already entered.
